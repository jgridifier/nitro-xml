## Caveats

- xlsx metric = **time to first view** (not full load): TS `loadWorkbook` loads the entire workbook; WASM `openDocument` calls `open_first_view` (lazy per-sheet parse; only the first visible sheet is parsed). Both timings reflect first-sheet availability. Rows labeled "time-to-first-view" in the cold-open table. See #283.
- Node cold-open numbers start after `initSync` — they do not include WASM fetch, compile, or instantiate. See the **Browser e2e** section for timings that include the full cold-start path in Chromium.
- docx XL (xl_a.docx): TS oracle rejects word/document.xml > 25 MiB — BLOCKED for cold open and peak memory. WASM opens the file; a one-sided WASM-only time is not useful. See #550.
- Save latency: not measured at M1 viewer stage — WASM save path not yet available. See draft issue.
- Platform: Linux x86_64 CI box; results may differ on macOS/Apple Silicon. The spec gates perf in Chromium.
- Known-loss exceptions per Jared #30: xlsx S peak_mem, docx S/M peak_mem — stay LOSS with numbers; they are not gate-blocking.
- Perf gate is in REPORT MODE (PERF_GATE_MODE=report). WASM-beats-TS is tracked but not enforced. Jared sets PERF_GATE_MODE=enforce when READY (see #8).
- CI reproduction: `scripts/ci/perf.sh record` now calls `compare_wasm_ts.sh` automatically (added in this follow-up PR).

## Method

- **Cold open (Node):** `perf/large/ts-vs-wasm.mjs`. xlsx metric = time-to-first-view: TS=`loadWorkbook` (full workbook); WASM=`openDocument` (open_first_view, lazy per-sheet). docx/pptx: cold open. After `initSync`; does not include WASM fetch/compile. N=21 runs (8 warmup-discarded). Statistics: median, p95, stdev, IQR.
- **Browser e2e:** `scripts/perf/browser_e2e.py`. Playwright headless Chromium; `performance.now()` at module-script start to first shadow-DOM content paint. Includes WASM fetch, compile, instantiate. Fresh browser instance per run (no HTTP cache, no V8 code cache). N=5 runs per fixture.
- **Peak memory:** `perf/large/peak-mem.mjs`. VmHWM from `/proc/self/status`, growth over post-init baseline; fresh child process per sample. N=7 runs. XL tier: xlsx + pptx measured; docx XL BLOCKED (#550).
- **Bundle size:** `perf/sizes.mjs`. raw + gzip (level 9) + brotli (quality 11). TS bundles: `perf/dist/ts/{xlsx,docx,pptx}.js`. WASM: `packages/nitro-xml/pkg/nitro_xml_wasm_bg.wasm` + `nitro_xml_wasm.js`. Loader: `packages/nitro-xml/loader/**/*.js` incl. `lazy/`.
- **WIN rule:** median(WASM)/median(TS) < 1 AND 95% CI upper < 1 (PRODUCT_SPEC §5). A tie is a fail.
- **95% CI:** Unpaired bootstrap: B=2000 resamples, deterministic seed (Mulberry32, seed=20261019). Each engine's samples resampled independently.
- **CI reproduction:** `scripts/ci/perf.sh record` calls `compare_wasm_ts.sh` automatically (added in this follow-up PR).
