## Definitions

- **Protocol group** = runs with the identical protocol key of the regression gate (`protocolId` / `PROTOCOL_FIELDS` in `perf/gate.mjs`; the same function is used here, in `BASELINE.md` and in the gate). **Samples of different groups are never pooled.** A **fixture-cell** is fixture x mode x CPU throttle x protocol group; each has its own n. A fixture measured under two groups in one cell is two fixture-cells.
- **n** = samples in one fixture-cell (history `n`). **thin** = n below the harness default iterations (cold 10, warm 20; `perf/run.mjs`), descriptive-only. **full-n** = at or above it. No other sample threshold is used or invented.
- **Excluded cell columns** count fixture x mode x CPU cells with **no samples in any group**, by their status in `failure-provenance.json` (a cell with a failure record that also has samples, e.g. a timeout later measured by the re-run, is counted in "also measured"). observed_error is deterministic (engine limit or throw, e.g. the 25 MiB docx limit): a rerun would not change it. observed_timeout is the harness hitting its timeout; **why** (TS slowness vs box pressure vs harness) is unresolved. operator_aborted = killed before finishing, nothing saved. not_run = never started.
- **Baseline** = how many measured fixture-cells have an entry on branch main in the same protocol group. The gate needs an *identical* protocol key; existing entries record no fixture hash, so a new entry that records one will report `no comparable baseline` until like-for-like main entries exist.
- **Category** (structural, one per row): `usable descriptive (full n)` = at least one fixture-cell is full-n; `descriptive only (thin)` = measured fixture-cells exist but all are thin; `unresolved` = nothing measured and at least one observed_timeout / operator_aborted / unknown cell; `no data` = nothing measured and only deterministic errors or never-run cells (or nothing recorded).

## Coverage caveats for the "usable descriptive" rows

The category says some fixture-cell in the row is full-n; it says nothing about how many fixtures of the row have no samples. Rows where more fixture x cell combinations have no samples than fixture-cells have samples: xlsx S warm 1x (13 measured fixture-cells, 23 cells without samples); xlsx S warm 4x (1 measured fixture-cells, 35 cells without samples); xlsx M warm 4x (2 measured fixture-cells, 8 cells without samples). These rows describe only the few measured fixtures.

## Historical harness identity limitation

History entries record no harness version or commit, no scroll cap or hint mode, no iteration design, no Playwright version and no viewport (the chunk result files hold iterations, Playwright and viewport, but they were never copied into history). The explicit `rerun` flag is the only recorded proxy for the harness definition: necessary for separating the original sweep from the scroll-fixed re-run, not shown to be sufficient. L/XL entries were appended from a non-main branch with the appending machine's host and no fixture hash. Do not infer a harness version for old entries.

No backfill of old entries with guessed values.
2. **Append the existing L/XL results from main** (`ts-lxl-8961e71.jsonl`, 42 entries are currently on branch `issue-10-lxl-real` with the appender's host) using the run rows' own host and fixture hashes checked against the bytes measured at 8961e71. This moves existing data; it does not measure. It gives L/XL a main-branch baseline row in the table above (every L/XL baseline cell is now "no main entries").
3. **Persist per-fixture results as they finish** in `run.mjs`/`baseline-sweep.mjs` (the result file is only written at the end of a chunk, so a kill discards iterations that had finished; for the 4 operator_aborted L/XL cells whether any had finished is not determinable).
